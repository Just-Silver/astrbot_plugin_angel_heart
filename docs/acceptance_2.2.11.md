# 2.2.11-beta.1 验收清单

## 一、安装

在 AstrBot 插件管理里切到该分支（或用 Release 包），重启插件。

**验证点**

- [ ] 插件版本显示 `2.2.11-beta.1`
- [ ] 启动日志无 `AngelHeart` 相关报错
- [ ] 首页「天使之心」页能正常打开，联系人列表有数据

## 二、重点一：接话率是否提升（本轮核心）

本轮改了 `behavior_rules.md` 的「绝对不参与任何未提及我的话题」，这是唯一直接影响门闩的改动。

**观察方式**：在同一个群里正常聊十几分钟，看日志。

```
docker logs -f <astrbot容器名> 2>&1 | grep "秘书决策"
```

- [ ] 进场后（被 @ 过一次的 60 秒内），别人聊**你关心的话题**时，出现了 `action=reply`
- [ ] 没人聊相关话题时，仍然 `action=no_reply`（说明没变成话痨）

**判据**

| 现象 | 结论 |
| --- | --- |
| 明显比之前爱接话，但仍在相关话题内 | ✅ 改动生效 |
| 完全没变化 | ⚠ 可能 `enter_on_mention_only` 在拦（见第三节），或模型太保守 |
| 到处乱接、不管什么话题都说 | ❌ 放得太宽，需回调 `behavior_rules.md` |

## 三、重点二：提示词页

路径：插件页 → 左侧「插件设置」→ 顶部 tab 切到「提示词」

- [ ] tab 名是「提示词」不是「预览」
- [ ] 「配置」tab 里**看不到**「助理的身份与关注范围」这一组（已挪到提示词页）
- [ ] 「提示词」页顶部两个输入框能编辑，且内容与当前配置一致
- [ ] 下方「拼装结果 · 5 步链路」正常显示 5 个节点
- [ ] 第 2、5 节点标「不注入」，第 3、4 节点标「注入」
- [ ] 点「展开内容」能看到真实 prompt 文本
- [ ] **多个节点可以同时展开**（本轮修复，之前互斥）
- [ ] 展开内容是正文字体，不是等宽字体
- [ ] 「群聊」下拉默认选中了一个真实群聊（不是「不指定」）
- [ ] 选一个活跃群后，秘书节点里出现该群**真实的消息内容**
- [ ] 没有真实对话时，只显示 `<群友甲>` / `<已回应消息占位>` 这类占位，**不出现虚构人名**

**草稿联动**

- [ ] 改「回复策略指引」里的文字，下方秘书节点内容**立即变化**（无需保存）
- [ ] 切回「配置」tab，看到的是同样的值
- [ ] 右下角出现「保存更改」按钮
- [ ] 保存后刷新页面，改动仍在

> ⚠ 验收期间不要保存任何修改，除非你确实想改配置。

## 四、重点三：暗色主题跟随

- [ ] 插件页跟随 AstrBot 的明暗设置（在 AstrBot 设置里切主题，插件页跟着变）
- [ ] 插件页**内**的月亮/太阳按钮**消失**了（嵌入模式下主题交给宿主）
- [ ] 提示词页在暗色下文字清晰，没有深底深字
- [ ] 展开的 prompt 代码块背景与文字对比正常

## 五、重点四：上游四处修复

这四条是上游用户踩过的真实故障，验收重点是**不出现回归**。

### 5.1 仅 @ 无正文（上游 #79）

- [ ] 在群里只 @ 助理、不发任何文字，助理应正常回复
- [ ] 之后马上再 @ 一次，**仍然能回复**（之前会卡 300 秒）

### 5.2 摘要消息角色（上游 #82）

- [ ] 群聊上下文压缩过一次之后，正常对话不中断
- [ ] 没有出现「把摘要当成群友发言」的回复

### 5.3 图片折叠后不丢（上游 #78）

- [ ] 群聊发图 → 聊到触发上下文整理 → 再问「刚才那张图是什么」，助理仍能看到图
- [ ] 日志里能看到 `[图片] <缓存路径>` 出现在摘要中

### 5.4 调度中不清理图片（上游 #83）

- [ ] 发图后立刻追问（工具续轮场景），不出现 400 错误
- [ ] 日志里能看到 `会话调度中，媒体缓存清理延后`

## 六、回归检查

- [ ] 私聊正常回复
- [ ] 群聊点名正常回复
- [ ] 离场状态下发普通消息，助理不插话
- [ ] 配置页其他分组（回复长度、能量、节奏）能正常保存

## 七、通过标准

**必须全绿**：第二节（接话率）有明确结论 + 第三、四节无异常 + 第五节四项无回归。

第二节若「完全没变化」，属于**未达预期但不阻塞发布**——记录下来，下一步再调 `decision_logic.md` 步骤二的「有犹豫就 false」。

## 八、发现问题时

把现象 + 日志片段发回，不要自己改。典型日志位置：

```bash
docker logs <容器名> 2>&1 | grep -E "秘书决策|助理防抖判定|巡检判定"
```
